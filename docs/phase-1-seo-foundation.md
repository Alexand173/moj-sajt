# Phase 1 SEO Foundation

This document records the repository changes and the manual deployment work for the 200-daily-visitor SEO target.

## Implemented in the repository

- News detail pages publish `NewsArticle` JSON-LD only when a validated `ai_content` rewrite exists.
- A rewrite must be marked `ai_status: generated`, `ai_generated: true`, and contain at least 200 words before the article is treated as indexable editorial content.
- Source-only or thin fallback pages are marked `noindex, follow` and show attribution plus the original source link instead of reproducing publisher copy.
- Festival detail pages publish `MusicEvent`, `VideoObject`, and `BreadcrumbList` JSON-LD when the database row contains the corresponding date/video fields.
- News and festival detail routes use breadcrumb structured data where the page has stable route context.
- Above-the-fold media is marked eager/high priority where appropriate; secondary images and YouTube iframes are marked lazy.
- Image containers keep explicit aspect-ratio or fixed-height wrappers where the current design already provides them, reducing layout shifts without changing the visual system.

## Google Search Console checklist

1. Open the verified `https://musictop.net` property in Google Search Console.
2. Go to **Indexing → Sitemaps** and submit `https://musictop.net/sitemap.xml` (or enter `sitemap.xml`).
3. Use **URL inspection** for the homepage, representative chart, news, festival, and tour URLs.
4. Select **Test live URL**, resolve any crawl or mobile usability warnings, then request indexing for the priority URLs.
5. Recheck the **Pages**, **Sitemaps**, **Core Web Vitals**, and **Enhancements** reports after the deployment is live.

The sitemap and robots endpoints are generated by Next.js. They must be checked on the deployed domain, not only on localhost.

## Cloudflare performance checklist

Cloudflare is not configured by repository code in this pass. In the Cloudflare dashboard:

- Point the DNS records at the production host and use SSL/TLS mode **Full (strict)**.
- Enable Brotli, HTTP/2 or HTTP/3, and standard static-asset caching.
- Cache immutable Next.js static assets; do not cache authenticated pages or `/api/*` routes.
- Keep the origin cache rules compatible with dynamic news and Supabase-backed routes.
- Measure the deployed site with Lighthouse mobile and PageSpeed Insights after each cache change. The target is LCP/page load under 2.5 seconds on representative mobile pages, not a localhost-only score.
- Only proxy or transform third-party images when their license and source terms allow it. Do not rewrite publisher image URLs blindly.

## Content quality gate

- `LATEST` stories are indexable only after the existing OpenAI rewrite pipeline stores a validated rewrite.
- The rewrite must be substantially different from the source and at least 200 words. The current generator requests a longer professional article; the 200-word threshold is the minimum safety gate for indexability.
- When the rewrite is unavailable, MUSIC TOP should link to the publisher and avoid displaying the publisher body as original content.
- Editors should add a distinct angle, context, and significance to reach the 800-word target for feature and evergreen articles.
- Do not add invented facts, quotes, reactions, or background information to meet a word count.

## Editorial publishing operations

The existing news fetch and AI enrichment workers remain unchanged. A daily article cadence still requires an editorial queue, source review, and monitoring of the existing worker output. Production automation should not publish unvalidated fallback text as an original article.

## Newsletter handoff

The current footer form remains a visual placeholder because no Beehiiv publication or public subscription endpoint was supplied. To connect it safely:

1. Create or select the Beehiiv publication.
2. Copy the public subscribe/form URL or configure a server-side API integration with its secret stored in Vercel environment variables.
3. Add consent copy and a link to `/privacy` before collecting addresses.
4. Confirm double opt-in, unsubscribe behavior, rate limiting, and error states in production.
5. Test the form on mobile and desktop before promoting the “Weekly New Music Digest” or “Concert Alert Newsletter” lead magnet.

No Search Console, Cloudflare, Beehiiv, or credential changes are performed by this document.
